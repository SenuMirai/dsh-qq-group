# 红包识别与感谢

## 现在能做什么

- 识别群消息里的红包卡片：
  - `json` / `xml` 卡片中包含 `红包`、`redpacket`、`red_packet`；
  - 或消息段类型为 `redbag`、`red_packet`、`hongbao`。
- 识别后标记为 `[红包]`，不当作普通卡片。
- 在「接话」页开启后，用模型生成一句 20 字以内的自然感谢，并 @ 发红包的人。
- 感谢提示词明确要求：不要声称“抢到了/领到了/手气最佳”，不要提金额、AI、插件。

## 现在不能做什么

**不能真正领取红包。**

原因：

- 当前 NapCat 的 OneBot 扩展 action 列表里没有“领取红包”接口；
- 本地 NapCat 源码只有 `onGrabPasswordRedBag` 回调占位，没有对外 action；
- 红包领取属于 QQ 协议层操作，不是普通消息 API；
- 插件没有用 DOM/无障碍自动化去点红包，那种方案需要额外客户端，封号与维护风险都高。

所以当前行为是：

```text
识别红包 → 模型感谢 → 不领取
```

不会返回“抢到了”这种假结果。

## 设置

「接话」页 → 红包：

```text
启用红包识别与感谢
感谢概率（0~100%）
```

默认关闭；开启后只影响识别到红包的群消息，不影响普通聊天。

## 如果以后 NapCat 提供领取接口

需要补三件事：

1. 在 `src/qq/onebot.ts` 的 `parseMessage` 里保留红包的 `bill_no` / `url` / 发送者等字段；
2. 在 `QqBridge` 里增加 `claimRedPacket`，调用新的 OneBot action；
3. 把 `thankRedPacket` 改成“先领取，成功才说抢到；失败只感谢”。

在那之前，不会伪造领取结果。

## 隐私与风控

- 不记录红包金额到日记/记忆；
- 不把红包链接、账单号发给模型；
- 不自动点击外部链接；
- 如果平台出现验证码/风控，应立即停用。
