# 记忆架构

## 1. 三层记忆

### 短期上下文

- 每个群保存原始聊天轮次，默认上限 200 条 / 12000 tokens。
- 回复时只取最近 N 条：
  - 默认 24 条；
  - 短句自适应默认 4 条；
  - 1.24.4 起实际至少 32 条 / 8 条，并额外保留最近 60 条中的关键旧消息。
- 超过上下文但还没压缩的原文，**仍在内存文件里，只是不进入提示词**。

### 摘要 + 关键记忆

- 只有原始轮次超过 `memoryMaxTurns` 或 `memoryMaxTokens` 时才触发压缩。
- 压缩会把最旧的一段交给模型，产出：
  - `summary`：摘要，默认最多 2000 字；
  - `keyMemories`：关键记忆，默认最多 50 条。
- 关键记忆不是按时间自动衰减；但受 50 条上限限制，新的会挤掉旧的。
- 摘要会保留最近的一部分，旧摘要会被截断。

### memory-v3

- 按证据召回，带淡忘权重：
  - 基础半衰期 30 天；
  - 情绪半衰期 7 天。
- 淡忘只影响召回排序，**不会自动删除条目**；删除需要手动。
- 自动写入有每日聊天配额（默认 8 条）。

## 2. 为什么她会“没聊几句就忘”

1. 群消息密度高，24 条可能只覆盖几分钟。
2. 短句走自适应 4 条，关键消息容易被挤出。
3. 24 条只是提示词窗口，不是摘要触发线；超过 24 条不会立刻形成摘要。
4. 摘要只记大概，容易丢掉 URL、数字、具体约定。
5. 关键记忆只在压缩时产生；两次压缩之间可能没有新关键记忆。

## 3. 永久记忆（1.25.0）

独立文件：`permanent-memory.json`，按群/会话分开。

特点：

- 不参与摘要；
- 不参与 v3 淡忘；
- 不会自动删除；
- 容量满时只封存并提示，不覆盖旧内容；
- 支持手动新增、删除、多选 AI 合并；
- 自动记录主人和自定义 QQ 名单里的话；
- 同一人 10 分钟内的连续消息会合并成一条，减少占容量。

容量默认 200 条/会话。满了以后：

```text
自动记录暂停
旧记忆保留
UI 显示“已满”
手动删除或合并后恢复
```

## 4. 配置

```text
permanent.enabled       启用永久记忆
permanent.autoCapture   自动记录名单里的人和主人
permanent.people        额外重要的人（QQ 号）
permanent.capacity      每会话容量
permanent.recallLimit   每次最多注入几条
permanent.recallChars   每次最多注入多少字
```

## 5. 边界

- 永久记忆不是无限数据库；容量满后必须人工清理。
- 自动记录只保存重要的人说的话，不保存所有人的口水话。
- 机器人回复不会自动写回永久记忆；需要保存的结论请手动添加。
- 跨群不共享：主人私聊和不同群的永久记忆分开，避免隐私串群。
